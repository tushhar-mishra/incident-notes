# Production Incidents and Outages: From First Page to Senior On-Call

One self-contained learning path for production incidents. It goes from "what is an incident" to debugging calmly at 3 AM, learning from the most famous real outages, and explaining any incident confidently in a senior DevOps / SRE interview.

Start at **[INDEX.md](INDEX.md)**. Topic files are in [`notes/`](notes/), numbered in reading order.

**Status:** ✅ Complete: 93 topics in 5 parts. Incident basics → recurring production failures (the patterns) → famous real outages, grouped by pattern → on-call drills → interview readiness.

**Every real outage has the same shape:** ⚡ Core · Summary · Impact · Timeline · How it happened · Why it spread · How they found it · What they did to fix it · Permanent fix · In my stack · Follow-up questions · Source.

**Every recurring failure and drill has the same shape:** ⚡ Core · Symptoms · Analogy · How it happens · How to find it · How to fix it · How to verify the fix · Prevention · Follow-up questions.

> **Accuracy note:** every real outage is written only from the company's official postmortem (or an official regulator / court document), linked at the bottom of the topic. When a detail is not in the official source, the topic says **"not publicly disclosed"**. Sample command output is illustrative: it shows the *shape* of real output; your own terminal is the source of truth.
